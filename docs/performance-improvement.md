# SDIR 성능 개선 실측

2026-11-16. 같은 PC의 이전 배포와 최종 개발 후보를 비교했다. 전체 드라이브 검색을 끈 일반 탐색 상태이며, 실제 권한 승인 후의 전체 드라이브 색인 비용은 아직 측정하지 않았다.

| 항목 | 이전 | 최종 개발 후보 |
|---|---:|---:|
| 100,003항목 폴더 재진입 중앙값 | 1,621ms | 517ms |
| 600항목 폴더 재진입 중앙값 | 145ms | 145ms |
| 실제 OneDrive 35항목 폴더 재진입 중앙값 | 146ms | 143ms |
| 개발자 연결 없는 일반 실행 private bytes | 206.0MiB | 204.5MiB |
| 같은 조건 working set 합계 | 410.1MiB | 406.5MiB |

대량 폴더 전환 시간은 약68% 감소했다. 작은 로컬 폴더와 현재 OneDrive의 수ms 차이는 폴링 간격약30ms·시스템·공급자 변동을 고려해 성능 우위로 해석하지 않는다. 일반 실행 메모리 차이는 약1%로 작다. WebView2 기본 비용이 남아 있으므로 Q-Dir 수준의 메모리 사용량을 달성했다고 판단하지 않는다.

첫 패널에 측정 폴더, 나머지3개는 같은 빈 폴더인 4분할·자세히 보기, 외곽 Windows 창1400×900을 사용했다. 트리·검색 색인은 껐다. 전환은 각 조건의 같은 프로세스에서 주소 입력 후 전체 항목 수가 반영될 때까지이며 첫 왕복 제외5회 중앙값이다. 일반 메모리는 개발자 연결 없이 가시 창 확인10초 후, 예열 제외3회다. 앱·작업자·WebView2 자손을 합산하며 private bytes는 물리 RAM 상주량과 다르고 working set에는 공유 페이지 중복이 있다. 캐시가 유지된 연속 실행이며 재부팅 직후 측정이 아니다. 빌드가 겹친 탐색 측정은 제외하고 전후 측정을 다시 실행했다. 최종 집계에 사용한14개 앱 시도는 모두 정상 종료했다.

목록 작업자만 분리한100,003항목 시험에서는 전달량37.7MB→3.7MB, 배치391→99개로 줄었다. 같은 부모 경로와 JSON 필드명을 항목마다 되풀이하지 않고, 첫256개·이후최대1,024개씩 전달한다. 비정상 UTF-16 파일명도 원래 코드 단위를 보존한다. 작업자 완료 중앙값은 약508→277ms였다. 이 수치를 화면 전체 완료 시간으로 해석하지 않는다.

자세히 보기의 렌더 행 수는 화면 높이에 맞춰 줄였고, 실제 키 입력·End·창 축소 후 선택 행을 다시 화면 안에 맞춘다. 최소화할 때 WebView2의 지원되는 Low 메모리 정책을 요청하고 복원 시 Normal로 되돌린다. 메모리 회수는 런타임과 운영체제의 판단이며, 최소화 전후 단일 시점 차이를 이 API만의 효과로 단정하지 않는다.

기존 Q-Dir 비교와 클라우드/NAS 시험 한계는 [이전 실측](performance-comparison.md)을 따른다. 이번 성능 개선으로 공급자별 오프라인·인증 만료·NAS 지연이 해결됐다고 주장하지 않는다.

최종 개발 후보 SHA-256: `85f96b57ed0505a8554f0411bceb87ea952994b79cb02d7a51bb67b3db0ab55a`.
집계와 원시 자료는 로컬 `docs/task-id/performance-optimize/{final-improvement-summary.json,before,before-guarded,accepted}`에 보관한다. 개인 경로·프로필 원문은 배포 문서에 포함하지 않는다.

메모리 집계에서는 PID 재사용으로 다른 사용자 앱이 섞인 중간 자료를 확인해 대체했다. 위 메모리 수치는 부모/자식 생성 시각과 살아 있는 프로세스의 시작 시각이 일치하는 자손만 합산하는 수정된 측정기로 전후 모두 다시 잰 결과다. 두 조건의 각 표본은11개 프로세스였으며 원시 자료에 생성 시각과 검사 방식을 함께 기록했다.
