# SDIR / 설치된 Q-Dir 실제 비교 측정

측정일: 2026-11-16. 아래는 성능 개선 전 배포(b158…)의 기록이다. 최신 후보 전후 수치는 [후속 실측](performance-improvement.md)을 따른다. 이전 배포 SDIR은 메모리 측면에서 Q-Dir보다 가볍지 않다. 개발자 연결을 끈 일반 실행의 전용 커밋 메모리는 SDIR이 약13.6배였고, 10만 항목 폴더로 돌아가는 시간은 약2.96배였다. 작은 폴더와 현재 연결된 OneDrive의 전환 차이는 약30ms 수준이므로 큰 우위로 해석하지 않는다.

## 같은 PC에서의 조건

- Windows 11 Pro 26300, Intel(R) Core(TM) i5-9600K CPU @ 3.70GHz, 논리 프로세서6개, 사용 가능 RAM 약31.9GiB, C: NTFS.
- 설치된 Q-Dir 11.14 / 파일 버전11.1.4.0 x86와 SDIR 0.1 Preview x64 release. 최신 Q-Dir과 비교한 결과가 아니다.
- 양쪽4분할·자세히 보기. 첫 패널에 측정 폴더, 나머지3개는 같은 빈 테스트 폴더. 외곽 창은 동일 Win32 관측 좌표1400×900, 소유한 테스트 창만 임시 topmost로 표시했다. SDIR 트리와 검색 색인은 닫았다.
- 설정과 실행 파일을 별도 폴더로 분리했으며 실행 파일 바이트는 원본과 동일하다. 현재 사용 중인 Q-Dir 창은 제어하지 않았다.
- OS/앱 캐시와 프로필을 유지한 연속 재실행이다. 재부팅 직후·캐시 삭제 후의 콜드 스타트가 아니다. 시작은 예열1쌍 제외 후 앱당 조건별4회, AB/BA 순서 각2회.
- 전환은 앱/조건당 한 프로세스에서 빈 폴더로 나갔다가 대상에 재진입했다. 첫 왕복을 제외한5회다. 서로 다른5개 프로세스를 표본으로 삼은 결과는 아니다.
- 목록 준비는 전체 항목 수가 반영되고 두 번 연속 확인된 시점이다. Q-Dir은 네이티브 목록 컨트롤, SDIR은 CDP로 DOM을 관측한다. 화면 그리기 완료·모든 파일의 추가 Shell 속성 완료 시점은 아니다.
- 폴링 간격은 약30ms이고, 네이티브 RPC/CDP의 관측 비용이 포함된다. 미세한 수십ms 차이를 엔진 성능 차이로 단정하지 않는다.

## 시작부터 목록 준비까지

단위: 초. 중앙값 [최소–최대], 예열 제외 각4회. SDIR 관측에 개발자 연결을 사용하므로 순수 무계측 시작 시간과 구분한다.

| 폴더 | Q-Dir | SDIR |
|---|---:|---:|
| 로컬 600개 | 1.458 [1.432–1.819] | 0.872 [0.763–1.453] |
| 로컬 100,003개 | 1.424 [1.377–1.451] | 2.242 [2.128–2.312] |
| OneDrive 35개 | 2.076 [1.427–3.146] | 1.481 [0.846–9.321] |

OneDrive의 가장 느린 SDIR 시도는 총9.32초였고 네이티브 가시 메인 창을 관측한 시점이8.89초였다. 이를 OneDrive 목록 I/O나 CDP 연결 하나의 원인으로 단정하지 않는다. 연속 프로세스 재시작·공유 프로필/시스템 상태 등의 원인 분리는 추가 프로파일링이 필요하다.

## 일반 실행 메모리

개발자 연결을 끄고 동일600개 폴더/4분할로 실행했다. 가시 창 관측10초 후 측정, 예열1쌍 제외 각3회 중앙값이다. 이 보조 실험에서는 DOM 완료 시점을 별도로 계측하지 않았다. 합계는 앱과 살아 있는 자식 프로세스이며 SDIR의 WebView2와 작업자를 포함한다.

| 지표 | Q-Dir | SDIR |
|---|---:|---:|
| 전용 커밋 메모리 | 15.2 MiB | 207.5 MiB |
| Working set 합계 | 46.3 MiB | 410.0 MiB |
| 위 전용 커밋 중 WebView2 | 0 MiB | 193.8 MiB |
| 위 전용 커밋 중 앱/작업자 | 15.2 MiB | 13.8 MiB |

전용 커밋 메모리는 현재 물리 RAM 상주량과 다르다. Working set 합계에는 공유 페이지가 중복될 수 있으며, DWM·이미 실행 중인 OneDrive·공유 Shell 서비스 등 자손이 아닌 프로세스와 GPU 전용 메모리를 전체 비용으로 합산하지 않았다. 구성 요소별 중앙값은 서로 다른 시도의 값이므로 각 중앙값의 단순 합은 전체 중앙값과 조금 다를 수 있다.

## OneDrive·응답 없음·남은 범위

실제 OneDrive의 표시 항목35개 폴더를 탐색했다. 사전/사후 온라인 전용·회수 관련 속성 항목은16개였다(사후 OFFLINE 16, recall 16). 파일 열기·내용 검색 명령이나 네트워크 차단은 수행하지 않았다. 공급자의 내부 다운로드/네트워크 I/O는 추적하지 않았다. 작은 폴더의 메타데이터 탐색이며 대량 클라우드 다운로드 시험이 아니다.

이번 시나리오에서 Windows의 지속적인 응답 없음은 재현하지 못했다. WM_NULL은 네이티브 메인 창의 메시지 응답만 검사하므로 렌더러·입력 초점·파일 작업 취소의 응답성을 보장하지 않는다. NAS 경로가 지정되지 않았고 현재 매핑된 NAS 드라이브도 없어 NAS 실측은 하지 않았다. 실제 공급자 오프라인·인증 만료·다운로드·대용량 부분 취소는 별도 재현 조건이 필요하다.

CPU는 원시 자료에 목록 완료2.5초 후부터 약2.5초 동안의 자손 CPU 누적 차이로 남겼다(논리 코어1개=100%). 시작 직후 백그라운드 작업과 프로세스 생성/종료 영향을 받을 수 있으므로 장시간 유휴 CPU나 입력 지연의 결론으로 사용하지 않는다.

## 해석과 다음 개선 순서

1. 메모리 목표를 먼저 잡아야 한다. 일반 실행에서도 WebView2가 전용 커밋 대부분을 차지한다. 현재 Dioxus Desktop 구성은 Q-Dir 수준의 메모리 목표를 충족하지 못했다. UI 렌더러/구성의 기본 비용을 따로 평가해야 한다.
2. 대량 목록 로드·전환 경로를 프로파일링하는 것이 우선이다. 10만 항목에서의 SDIR 전환 지연은 같은 프로세스의 반복에서 일관되게 관측됐다. 디렉터리 열거·메타데이터·직렬화/IPC·정렬/렌더 중 어느 단계가 지배적인지는 아직 분리 측정하지 않았으므로 특정 단계의 원인으로 확정하지 않는다.
3. 자주 멈추는 실제 클라우드/NAS 경로에서 사용자 여정을 재현해야 한다. 현재 OneDrive35항목 결과로 클라우드 멈춤 문제가 해결됐다고 판단할 수 없다.

## 재현·증거

현재 Windows 작업 폴더에서 입력/복사본이 보존된 상태로 실행한다. `fixture.json`과 환경 인벤토리, 앞 작업의 합성10만 항목 폴더가 입력이다. 다른 PC에서 입력 없이 바로 실행하는 범용 벤치마크 설치기는 아니다.

```powershell
node scripts/performance-compare.mjs --visible
node scripts/performance-compare.mjs --navigation
node scripts/performance-compare.mjs --normal-memory
python docs/task-id/performance-compare/summarize.py
```

집계: [summary.json](task-id/performance-compare/summary.json). 원시 자료: [시작/목록](task-id/performance-compare/visible-results.json), [폴더 전환](task-id/performance-compare/navigation-results.json), [일반 메모리](task-id/performance-compare/normal-memory-results.json). 개인 경로가 있는 원시 자료는 이 PC의 무시된 task-id 폴더에 보관한다. 공개용 요약에는 해당 경로·파일명·설정 내용을 싣지 않는다.

중간 측정기 실패와 조건 고정 전42회/전환 탐색 결과도 별도 로그로 보존했으며 최종 중앙값에 합산하지 않았다. 초기 보강에서 종료 대기1건이 발생했고 당시 메인 창의 정확한 대상이 남지 않아 원인은 확정하지 못했다. 이후 초기 프로세스 경로 조회·메인 HWND 고정·소유 PID 확인을 보완했다. 최종44개 프로세스 시도(시작30+전환6+일반 메모리8)는 모두 정상 종료했고 남은 소유 프로세스는0개다. 사용자 원래 Q-Dir의 두 설정 파일 해시는 동일하며 제품 소스/배포 실행 파일은 변경하지 않았다.

SDIR SHA-256: `b158955e2b1c66883c7240ad1d7d77341d7934c1b881100c3eb726101313f8fb`. Q-Dir SHA-256: `f3b99e3609cb97ce557bb938163ddb6d7fb408789767c2da2d6792930c363fe6`.

측정용 복사본/매개변수 구성 참고: [Q-Dir 공식 시작 경로 매개변수](https://www.softwareok.com/?faq=54&seite=faq-Q-DIR), [공식 포터블 설정 위치](https://www.softwareok.eu/?faq=142&seite=faq-Q-DIR). 비교 수치는 웹 문서의 수치가 아니라 이 PC에서 관측한 값이다.
