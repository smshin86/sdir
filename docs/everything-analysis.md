# 설치된 Everything 분석과 SDIR 적용

2026-11-17. 사용자가 설치한 `C:\Program Files\Everything\Everything.exe` 1.4.1.1032 x64를 `reverse-engineer-anything`으로 분석했다. 실행 파일은 2,272,424 bytes이며 SHA-256은 `f191f756996a14a11e5445fa7103d302efd510cf2fbf920e6c0c8ed51d512e36`이다.

설치 폴더에는 원본 C/C++ 소스나 PDB 파일이 없었다. 아래의 함수 분석은 Ghidra가 복원한 의사코드와 참조 관계이며, 제작자의 원본 소스와 구분한다. REA는 3,070개 함수와 4,841개 정의된 문자열을 관측했다. 정의되지 않은 문자열·간접 호출·원래 변수명·형식은 복원 범위 밖일 수 있다.

## 직접 확인한 내용

| 근거 | 관측 | SDIR 반영 |
|---|---|---|
| 설정 파일 및 실행 중인 서비스 | `run_as_admin=0`, Everything 서비스 실행 중 | 기존 일반 권한 파일 관리자와 관리자 검색 호스트 분리 유지. Everything 서비스 설치·설정은 변경하지 않음 |
| 설정 `monitor_thread_mode_background=1`; 함수 `0x14004fb70` | 조건부 `SetThreadPriority(...,0x10000)` 요청, 종료 시 `0x20000` 복원 | 검색 호스트의 색인 스레드에 Windows 백그라운드 I/O 정책 요청. 실패해도 검색을 차단하지 않으며 적용한 정책은 반환 시 복원 |
| 설정 `db_update_thread_priority=-15`; `0x14004b4a0` → `0x140012910` | USN 처리 함수가 우선순위 변환 후 `SetThreadPriority` 호출 | UI와 색인을 같은 작업 경로로 합치지 않고 별도 호스트 유지. CPU 수치만 낮추는 대신 I/O·메모리 스케줄링도 조절하는 위 정책 사용 |
| 설정 `monitor_retry_delay=30000`; 함수 `0x14004b700` | 오류 로그에 30초 재시도 안내, 핸들 해제와 재시도 기준 시각 기록 | 오류 볼륨은 매 5초 발견 주기마다 다시 열지 않고 30초 뒤 재시도. 실제로 다시 연결된 Offline 볼륨은 즉시 재개 가능 |
| `monitor_update_delay=1000`, `search_as_you_type=1` | 변경 읽기와 입력 반영에 별도 설정 존재 | 기존 SDIR의 최신 입력 폐기·검색 갱신 간격·200개 표시 상한 유지. Everything의 수치를 그대로 복사하지 않음 |
| `index_size=1`, `index_date_modified=1`, 생성/접근일·속성 색인 비활성 | 선택 메타데이터와 빠른 정렬이 설정으로 분리됨 | 관측 사항으로 기록. 크기·날짜 검색 옵션과 영구 DB를 새로 구현했다고 표시하지 않음 |

INI 의미는 [Everything 공식 설정 문서](https://www.voidtools.com/en-uk/support/everything/ini/), 백그라운드 정책은 [Microsoft SetThreadPriority 문서](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-setthreadpriority)와 대조했다. Everything 설정에서 관측한 선택값은 사용자의 현재 설정이며 모든 설치의 기본값으로 일반화하지 않는다.

## 인터페이스 설정에서 추가로 적용한 항목

사용자가 제공한 Everything 인터페이스 설정 화면과 설치된 INI를 대조했다. 처음의 검색 엔진 검증이 이 화면의 모든 설정을 검증했다는 뜻은 아니다. SDIR에는 다음 항목을 별도로 구현하고 사용자 여정으로 검사한다.

| 항목 | SDIR에서의 동작 |
|---|---|
| 입력 즉시 검색 | 기본 켜짐. 끄면 통합 검색은 Enter나 검색 버튼을 누를 때 실행. 색인이 끝나도 제출하지 않은 입력은 실행하지 않음 |
| 검색창 전체 선택 | 기본 켜짐. 처음 초점이 들어올 때 전체 선택하고 같은 검색창을 다시 클릭하면 커서 편집 가능 |
| 검색을 열 때 초점 이동 | 도구 모음에서 통합 검색을 열 때의 동작을 선택. Ctrl+Shift+F는 설정과 관계없이 검색창으로 이동 |
| 색인 메모리 상한 저장 | 256/512/1024/2048 MiB 선택을 자동 저장해 재실행 후 복원. 실제 색인에는 다음 시작부터 적용하며 재실행 때 자동으로 권한을 요청하지 않음 |
| 검색 설정 초기화 | 검색 설정만 기본값으로 복원. 폴더·탭·패널 그룹과 테마는 유지 |
| 볼륨별 결과 범위 | 볼륨 루트 기준 상대 경로를 포함·제외 목록으로 편집하고 저장 후 결과를 필터링 |
| 연결되지 않은 드라이브 정책 | 프로필에 저장된 정책을 볼륨 GUID와 함께 표시 |

드라이브별 포함·제외 경로는 색인된 볼륨 안에서 검색 결과만 필터링하며 색인 수집 범위는 바꾸지 않는다. 드라이브 정책은 프로필에 저장하지만 색인 데이터의 영구 저장, 오프라인 캐시 보존, USN 튜닝은 캐시 백엔드 구현과 Windows 런타임 검증 전까지 보류한다.

트레이 아이콘·닫아도 상주·다중 창·Windows 파일 열기 방식 변경은 이번 적용 항목이 아니다. 일반 창 활성화마다 검색창으로 이동시키는 대신 사용자가 명시적으로 검색 패널을 열 때의 초점만 설정한다. 현재 닫기 동작과 검색 호스트 종료·메모리 해제는 유지한다.

검사는 실제 클릭·키 입력, 화면의 결과·선택·초점, 디스크의 파일·설정과 재실행 복원을 함께 확인한다. 최소 980×580에서 설정을 조작하고 0.8초 안에 닫는 저장 여정, 글로벌 검색 입력창의 F5도 포함한다. 최신 실행 파일과 검사 결과는 [검증 상태](test-summary.md)를 따른다.

## SDIR 통신 결함의 재현과 수정

실제 관리자 인증 후 검색 상태가 전달되지 않는 현상을 발견했다. 동기 named pipe의 동일 파일 객체에서 읽기 대기 중 쓰기도 막히는 것을 `probe-duplex.ps1`로 재현했다. 복제 핸들로는 이 동작이 분리되지 않았다. SDIR 명령 수신과 상태 전송을 서로 다른 파이프 객체로 분리했으며, 양쪽 연결의 PID 확인·로컬 전용 ACL·Anonymous SQOS는 유지했다.

Windows 검사는 요청이 없는 동안 상태가 도착하는지, 이후 요청 전달과 EOF가 동작하는지, 관리자 토큰 위임이 차단되는지 확인한다. 백그라운드 정책의 실제 API 적용·복원과 오류 재시도 조건도 검사한다. 이 검사는 C/D/E 실제 MFT·USN 여정을 대체하지 않는다. 최신 실행 결과는 [검증 상태](test-summary.md)를 따른다.
