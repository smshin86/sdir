# SDIR 사용자 여정과 검증 기준

기능 버튼 존재나 컴파일 성공만으로 완료를 판정하지 않는다. 각 여정은 **시작 상태 → 사용자 조작 → 화면 결과 → 실제 파일·설정 결과**를 함께 확인한다. 새 기능과 수정은 이 표의 여정에 연결하고, 실패하면 수정 후 같은 여정을 다시 실행한다.

검증 상태는 `자동 통과`, `수동 확인 필요`, `미구현`으로 구분한다. 자동 통과도 이 문서의 입력·환경 범위에 한정한다. 아직 확인하지 않은 기능을 검증 완료로 표현하지 않는다.

| 여정 | 사용자 목적과 조작 | 화면에서 확인할 결과 | 파일·상태 확인 | 자동화·증거 |
|---|---|---|---|---|
| J01 작업공간 열기 | 실행 → 1·2·4분할 전환 → 탭 추가·닫기 → 즐겨찾기 추가 | 선택한 분할 수, 독립된 탭과 활성 패널, 저장한 즐겨찾기 | 분리된 프로필에 레이아웃·탭·즐겨찾기가 저장됨 | `scripts/ui-smoke.cjs`, `scripts/recovery-smoke.mjs`, 설정 왕복 테스트 |
| J02 폴더 탐색 | 폴더 선택 → Enter → 뒤로 → 없는 경로 입력 → 다른 패널 사용 → 복구 | 주소·목록이 같은 폴더를 가리킴; 오류가 난 패널 외에는 정상 동작 | 실제 임시 폴더의 파일과 경로가 일치; 이전 요청의 응답은 현재 폴더를 덮어쓰지 않음 | UI 취소·복구 여정, worker 목록·오류 테스트, `stale_reply_cannot_replace_new_folder` |
| J03 파일 찾기·선택 | 큰 폴더 필터 → 스크롤 후 필터 변경 → 정렬 → 항목 선택 | 항목 수와 행이 일치; 필터 변경 시 위로 이동; 정렬 방향과 관계없이 폴더 우선 | 필터로 파일이 변경되지 않음; 최대 80개 행/패널만 DOM에 생성 | 600개·10만 개 파일 UI 여정, 정렬 단위 테스트 |
| J04 파일 정리 | 새 폴더 → 이름 변경 → 파일 선택 → 옆 패널로 복사 → 이동 | 작업 중 상태 → 완료 후 목록 갱신 | 복사 원본 보존, 목적지 내용 일치; 이동 후 원본 경로가 없어지고 내용 보존 | UI 새 폴더·이름 변경·복사 + Windows IFileOperation 임시 파일 통합 테스트 |
| J05 삭제 전 확인 | 선택 → 휴지통 → 취소 | 확인 창과 취소 후 원래 목록 | 취소한 항목은 실제로 그대로 존재 | UI 확인 취소 + `audit-smoke.mjs`에서 실제 휴지통 이동·정확한 원래 폴더 확인·Shell 복원·내용 일치 자동 통과. 영구 삭제 확인 창은 수동 확인 필요 |
| J06 앱 안에서 검색 | 검색 열기 → 현재 폴더 색인 → 한글 검색 → 결과 클릭 | 설정에서 색인 상태 확인, 검색 결과 수 표시, 대상 패널에서 위치를 열고 파일 선택 | 반환 경로가 실제 선택한 폴더 아래의 파일과 일치; `ext:bin`도 일치 | UI 검색·결과 이동 여정 + 검색 worker 통합 테스트 |
| J07 변경·오류 다루기 | 파일 작업 후 재색인, 잘못된 이름·재귀 복사 대상 지정 | 오래된 색인 안내; 오류를 완료로 표시하지 않음 | 동일 폴더 이동·자기 하위 폴더 복사·잘못된 이름은 거절하고 동일 폴더 복사는 사본 생성 | 경로·이름 검증 테스트. 실제 동일 이름 충돌 창 닫기와 두 파일 보존은 `audit-smoke.mjs` 자동 통과. 덮어쓰기 승인·권한 거부·작업 도중 취소·부분 완료는 수동 확인 필요 |
| J08 다른 앱과 연계 | Windows 탐색기 ↔ SDIR 복사·잘라내기·붙여넣기, 외부 파일 드롭, 기본 앱 열기 | 선택과 붙여넣기 대상이 정확하며 복사/이동을 구별 | 원본·목적지 파일과 실제 내용 확인; 테스트 전 클립보드 상태 보존 | 파일 목록 클립보드는 J12에서 실제 Windows 교차 프로세스 자동 확인. 생성한 .cmd 파일의 ShellExecute 연계와 결과 마커는 자동 통과. 탐색기 UI·다른 연결 프로그램·OLE 드롭은 수동 확인 필요 |

## 복사·키보드·패널 검색 여정

| 여정 | 시작·조작 | 화면과 실제 상태 | 검증 방식 |
|---|---|---|---|
| J12 실제 복사·붙여넣기 | 파일 선택 → Ctrl+C → 다른 패널의 빈 영역 클릭 → Ctrl+V; Ctrl+X → 대상 탭 클릭 → Ctrl+V; 도구 모음 복사/붙여넣기·같은 폴더 사본 생성 | CF_HDROP와 Preferred DropEffect가 함께 유지; 복사는 원본 보존, 이동은 원본 제거, 실제 대상 내용 동일; 한글·여러 파일 포함; 성공 안내는 실제 기록 뒤 표시 | `clipboard-journey.ps1` + `navigation-smoke.mjs`, 별도 Windows 프로세스가 클립보드를 읽고 쓰며 실제 임시 파일을 확인 |
| J13 문자 키로 선택 | 목록 클릭 → j 반복 → ju 연속 → 방향키·Home·Shift+방향키 | 현재 필터 안에서 접두어와 반복 순환 선택, 가상 목록 바깥의 항목도 화면 안으로 이동 | 실제 CDP 마우스·키 입력, 화면 선택과 스크롤 위치 검사 + 모델 회귀 테스트 |
| J14 패널별 현재 폴더 검색 | 각 패널 Ctrl+F/F3 → 서로 다른 검색어 → 검색어 Ctrl+A·Delete → Esc → Ctrl+Shift+F | 패널·탭별 검색 독립; 입력창에서 파일 삭제·전체 선택이 실행되지 않음; Esc는 검색 초기화·목록 복귀, 통합 검색 단축키 구분 | 실제 입력·포커스 유지, 실제 원본 파일 보존, 결과 수와 입력 값 확인 |

실제 키보드 여정은 이벤트 핸들러를 직접 호출하는 방식만으로 통과 처리하지 않는다. `Input.dispatchMouseEvent`와 `Input.dispatchKeyEvent`로 클릭·포커스·기본 편집 동작을 함께 검사한다. 클립보드는 먼저 형식별 데이터를 메모리에 보존한다. 보존할 수 없는 형식이 있으면 쓰기 전에 중단하며, 테스트 중 다른 내용으로 바뀐 클립보드는 덮어쓰지 않는다.

## 자동 검증 실행

Windows에서 `scripts/build-windows.ps1 -Test`로 코어·프로세스·네이티브 파일 작업을 검사한다. 전체 후속 회귀는 `scripts/verify-journeys.ps1 -Executable <실행 파일>`로 순차 실행하고 결과를 `docs/task-id/journey-audit`에 모은다. `scripts/smoke-windows.ps1`은 별도 프로필과 새 임시 파일만 사용해 위 UI 여정을 실행한다. `-Large`는 실제 10만 파일을 생성한다. 화면 캡처·측정·검증 결과는 `docs/task-id/sdir-first-app`에 기록한다.

기본 UI 검사는 클립보드와 사용자의 기본 프로그램을 변경하지 않는다. 별도 J12 검사는 클립보드를 백업·복원하면서 실제 파일 형식을 검증한다. 실행하지 않은 탐색기 UI·기본 앱 검증은 통과로 처리하지 않는다. Windows 고유 대화상자에서의 덮어쓰기·권한·취소도 웹 화면 검사만으로 통과시키지 않는다.

## 수동 수락 검사

새 임시 폴더 A/B와 테스트용 파일로 진행한다. 사용자 원본 파일을 사용하지 않는다.

1. 탐색기에서 파일 복사 → SDIR의 B에 붙여넣기 → 원본 보존·대상 내용 일치 확인. 반대 방향도 확인한다.
2. 탐색기와 SDIR 각각에서 잘라내기 → 상대 앱의 B에 붙여넣기 → 원본 경로 제거·대상 내용 보존 확인. 한글·공백·여러 항목을 포함한다.
3. 같은 이름 파일이 있는 곳으로 복사 → Windows 충돌 창에서 취소 → 두 파일 내용이 보존되는지 확인한다. 덮어쓰기 선택 시 대상 내용과 결과 안내를 확인한다.
4. 큰 임시 파일 복사 중 Windows 진행 창에서 취소 → 앱에서 완료 성공으로 표시하지 않는지, 일부 처리 가능 안내와 실제 파일 상태가 일치하는지 확인한다.
5. 임시 파일 휴지통 이동 → Windows 휴지통에서 복원 → 원래 경로와 내용 확인. 휴지통을 지원하지 않는 장치에서는 영구 삭제 확인을 취소하고 원본 보존을 확인한다.
6. 탐색기에서 파일을 패널에 끌어넣기 → 복사 목적지 확인. 앱 밖으로 끌어놓기는 미구현이다.
7. 실제 바탕 화면·다운로드·문서가 OneDrive 등으로 이동한 PC에서 빠른 이동이 Windows 알려진 폴더와 일치하는지 확인한다.
8. 앱 종료·재실행 후 레이아웃·각 탭의 경로·즐겨찾기가 복구되는지는 자동 복구 여정에서 확인했다. 마지막 변경 직후 종료와 저장 실패 시 기존 설정 보존·안내·두 번째 닫기는 `fast-close-smoke.mjs`로 자동 확인한다. 평상시에는 최대 약 0.8초 지연 저장하며 정상 종료에는 최종 저장 결과를 기다린다.

## 다음 개발의 완료 조건

MFT/USN 실시간 색인, 영구 검색 DB, 외부로 드래그, 미리보기, NAS 최적화는 미구현이다. 각 기능은 대응 여정, 실패 경로, 실제 파일 결과, 측정 증거를 추가한 뒤 완료로 표시한다. 성능은 목록 최초 표시·완료, 필터 입력→DOM 갱신, 색인 생성, 검색 엔진 처리, 앱 전체 메모리를 구분해 기록한다.

J01은 980×580 최소 뷰포트 4분할에서 모든 파일 목록에 한 행 이상(여유 간격 기준38px) 보이는지도 측정한다. J02~J08의 추가 감사는 `scripts/audit-smoke.mjs`에서 이름·크기·수정일 양방향 정렬, 주소·뒤/앞/상위·없는 경로 복구, 잘못된 이름 보존, 실제 F2 한글 이름 변경, Shell 기본 연결 실행, 휴지통 복원 후 F5, 색인 범위·잘못된 쿼리 복구·갱신, 실제 네이티브 충돌 창 취소를 검사한다.

이번 환경의 실제 OLE 드래그는 소유한 앱 창을 안전하게 전면 활성화하지 못해 실행되지 않았다. 웹 이벤트로 대체해 통과 처리하지 않았다. OneDrive 특정 동기화 상태의 멈춤·NAS·권한 거부·복사 중 부분 취소·외부로 드래그는 추가 실제 환경 확인 또는 구현이 필요하다.

Windows는 사용자가 입력한 경로의 대소문자나 표기를 정규화할 수 있다. `IShellItem`의 정규 동일성으로 최종 결과의 부모 폴더를 확인하고 실제 최종 파일 이름을 목록 경로에 대응시킨다. 소문자로 입력한 대상 경로는 실제 UI 선택까지 검사하고, 그리스 문자 경로의 대소문자 동일성은 네이티브 작업 결과 회귀 테스트로 검사한다.

자세히·목록은 패널당 최대80행, 아이콘은 뷰포트와 열 수에 필요한 범위(최대512개)만 DOM에 만든다. 썸네일 파일 읽기는 추가하지 않는다. 패널 크기 관찰자는 패널별1개·최대4개로 교체 시 이전 관찰자를 끊고 패널 제거 시 해제한다. 참고 항목의 근거와 적용 범위는 [참고 기능 적용표](reference-features.md)에 기록한다.
