# SDIR 0.1 검증 기록

검증일: 2026-11-16. 초기 프리뷰부터의 누적 기록이다. 이전 절의 실행 파일·해시는 각 시점의 기록이며 최신 작업의 구현·검증 상태는 [최신 요약](test-summary.md)을 따른다. 모든 환경의 수락 검사가 끝났다는 의미는 아니다. 여정별 완료 기준은 [사용자 여정 검증표](user-journeys.md)를 따른다.

## 실행 환경과 산출물

- Windows x64, OS build `10.0.26300`, Intel Core i5-9600K, RAM 약 32GiB
- Rust MSVC 1.96.1, Dioxus Desktop 0.7.10, Edge WebView2
- goz-core commit `78ca353b8c0b227e47217c33c25d37fcff025e33`
- 실행 파일: `dist/SDIR.exe`, 7,461,888 bytes
- SHA-256: `92e816722fbd97b69826d0a3fa442311fd1997cb8131ea6d35bc04811c2fcb14`
- 설치·관리자 권한·Everything 서비스 없이 실행. 앱 데이터와 테스트 프로필은 분리함.

## 확인한 결과

Windows의 단위·프로세스·네이티브 파일 작업 테스트 14개, Linux/WSL의 단위·프로세스 테스트 14개가 통과했다. 네이티브 작업 테스트는 임시 폴더 안에서 한글 파일 복사, 이름 변경, 폴더 생성, 이동을 수행하고 실제 내용과 원본 보존·제거를 확인했다.

실제 Windows 실행 파일의 WebView 화면에서 600개와 10만 개 파일을 사용하는 사용자 여정을 실행했다. 두 실행 모두 다음 검사를 통과했으며 JavaScript 런타임 예외는 관측되지 않았다.

- 1·2·4분할 전환, 탭 추가·닫기, 즐겨찾기 저장
- 없는 경로의 오류 표시와 다른 패널의 정상 조작, 뒤로 이동으로 복구
- 폴더 진입·뒤로 이동, 필터 결과와 항목 수 일치, 스크롤 후 필터 변경 시 위치 초기화
- 새 폴더·이름 변경·옆 패널 복사: 화면 결과와 실제 임시 파일 결과 일치
- 휴지통 확인 창에서 취소: 실제 원본 보존
- 내장 색인·한글 검색·결과 클릭: 옆 패널에서 실제 파일을 선택
- 가상 목록: 패널당 DOM 행 최대 80개

추가 복구 여정은 10만 파일 폴더를 읽는 도중 취소하고, 늦은 응답으로 목록이 바뀌지 않는지 확인했다. 취소 후 다른 폴더로 이동해 실제 내용이 표시되는지 검사했다. Windows 창에 정상 닫기 요청을 보낸 뒤 앱을 재실행해 2분할·탭 경로·즐겨찾기·실제 폴더 내용이 복구되는 것까지 통과했다.

## 측정값과 해석

아래 값은 이 PC의 로컬 임시 폴더에서 한 번 실행한 탐색적 측정이다. 동일 크기의 실제 사용자 폴더, NAS, 콜드 캐시, 다른 PC의 성능을 보장하지 않는다. 10만 파일을 생성한 직후 읽었으므로 파일 시스템 캐시의 영향을 포함한다.

| 항목 | 600개 파일 | 10만 개 파일 |
|---|---:|---:|
| 앱 실행 → 첫 패널 전체 목록 완료 | 약 1.00초 | 약 8.06초 |
| 필터 입력 → DOM 갱신 p95, 20회 | 17.8ms | 22.0ms |
| 선택 폴더 색인 완료, UI 폴링 포함 | 약 0.089초 | 약 7.12초 |
| `보고서` 검색 엔진 처리, 한 번 | 0.4ms | 0.6ms |
| 검색 엔진 색인 내부 버퍼 | 81.5KiB | 11.4MiB |

필터 시간은 WebView 안에서 input 이벤트를 발생시킨 때부터 결과 항목 수의 DOM 변경을 관측한 때까지다. 실제 키보드·IME 입력·픽셀 페인트·최초 목록 완료 시간은 포함하지 않는다. 검색 엔진 처리 시간은 입력 debounce·IPC·화면 갱신을 포함하지 않는다. 색인 내부 버퍼 수치는 프로세스 전체 메모리가 아니다.

일반 실행도 별도로 측정했다. 검사 포트를 끄고 4개 패널에 각 600개 파일을 표시한 뒤 약 13초 시점의 앱+WebView 하위 프로세스를 합산했다. 검색 색인은 생성하지 않았다.

| 메모리 구분 | 일반 실행, 검사 포트 꺼짐 | 10만 파일 여정 후, 검사 포트 켜짐 |
|---|---:|---:|
| Private bytes 합계 | 약 208MiB | 약 292MiB |
| Working set 합계 | 약 376MiB | 약 479MiB |

Private bytes는 프로세스 전용 커밋 메모리로, RAM 상주량과 같지 않다. Working set 합계는 공유 페이지를 중복 계산할 수 있어 앱의 고유 RAM 점유량으로 해석하면 안 된다. 각 값은 한 시점의 스냅샷이다. 일반 실행에서 약 10.77초 동안의 CPU 누적 시간 증가는 0.0625초였으며, 논리 코어 하나 기준 평균 약 0.58%였다.

현재 결과는 큰 폴더의 필터 응답성을 뒷받침하지만 **초경량 메모리 목표 달성을 입증하지 않는다**. 메모리 사용량이 가장 중요한 조건이면 WebView 기본 비용을 줄일 수 있는지 확인하고, 동일 코어를 이용한 다른 Windows UI 구현과 비교해야 한다. 이번 버전에서 그 비교까지 수행하지 않았다.

## 미확인·미구현 범위

Windows 클립보드를 통한 실제 교차 앱 복사·잘라내기·붙여넣기, 외부 드롭, 기본 앱 열기, 휴지통 복원, Windows 충돌·권한·작업 도중 취소·부분 완료 대화상자는 아직 수동 수락 검사가 필요하다. 사용자 클립보드와 기본 프로그램을 자동으로 변경하지 않았고, 이 항목들을 통과로 집계하지 않았다.

NAS·오프라인 경로의 실제 장시간 I/O, 대용량 파일 취소, 다중 모니터·고해상도·스크린리더·실제 한글 IME 여정은 미측정이다. MFT/USN 전체 드라이브 실시간 색인, 영구 DB, 외부로 드래그, 미리보기는 미구현이다. 현재 색인은 세션 스냅샷이므로 외부 파일 변경도 다시 색인해야 한다.

## 증거 파일

로컬 `docs/task-id/sdir-first-app`에 `windows-verified-build.log`, `linux-test-final.log`, `ui-smoke.json`, `ui-large.json`, `ui-recovery.json`, `memory-normal.json`, `artifact.json`과 각 UI PNG를 보관한다. UI 자동화 초기 실패는 새 화면을 연 직후 렌더링을 기다리지 않은 테스트 경합이었다. 요소가 활성화될 때까지 기다리도록 수정한 뒤 같은 여정이 통과했다.


## 그룹·설정·목록 조회 개선 후속 검증

Windows check와 테스트 16개(단위 12개+프로세스/네이티브 작업 4개), Linux 테스트 15개(단위 12개+프로세스 3개)가 통과했다. 이번에 추가한 Windows 회귀 테스트는 디렉터리를 열거한 뒤 실제 파일을 제거하고도 열거 결과의 메타데이터를 읽을 수 있음을 검사한다. 파일을 다시 여는 구현은 이 검사를 통과할 수 없다. [Rust 공식 문서](https://doc.rust-lang.org/std/fs/struct.DirEntry.html#method.metadata)도 Windows의 `DirEntry::metadata`는 추가 시스템 호출이 필요 없음을 명시한다.

추가 Windows 사용자 여정에서 네 그룹 이름, 공백 정리·한글·이모지·빈 이름 기본값, 저장·취소, 그룹 내부 독립 탭, 1/2/4분할 전환, 정상 종료·재시작을 검사했다. 테마는 밝게·어둡게와 시스템 테마 변경 모사를 모두 확인했다. 목록 간격 38px에서 실제 행 높이·전체 가상 높이·스크롤 오프셋이 일치하며, 숨김 옵션은 접힌 패널에도 반영된다. 저장된 설정 JSON과 재실행 화면 모두 일치했다. 이전 v1 설정의 경로·숨김 설정은 새 기본 설정과 함께 보존된다.

동일 PC에서 이전 실행 파일과 새 실행 파일의 읽기 전용 작업 프로세스를 한 번씩 비교했다. 사용자 파일 이름은 결과에 기록하지 않았고, 폴더 목록의 항목 수·시간만 집계했다. 하위 폴더를 자동 탐색하거나 파일 내용·썸네일을 읽지 않았다.

| 범위 | 이전 구현 | 메타데이터 재사용 후 | 해석 |
|---|---:|---:|---|
| OneDrive 최상위 11개 항목 | 약 22.4ms | 약 15.7ms | 두 구현 모두 정상 완료. Q-Dir 응답 없음 재현 증거가 아님 |
| 로컬 임시 폴더 100,003개 항목 | 약 8.76초 | 약 0.41초 | 별도 파일 속성 재조회 제거 후 조회 시간 감소 관측 |

이 값은 프로세스 시작·JSON 전송을 포함하며 화면 표시 시간은 제외한다. 이전→신규 순서의 단일 비교여서 캐시·실행 순서 효과를 통제한 벤치마크가 아니다. 따라서 클라우드 전체에서 같은 개선 비율을 보장하지 않는다. OneDrive와 Q-Dir은 확인 시점에 실행 중이었고 둘 다 Responding=true였다. 특정 동기화 폴더·파일 상태·Q-Dir UI 대기 스택이 확보되지 않아 실제 멈춤 원인은 미확정이다. 기존 REA의 정적 분석도 인과관계를 입증하지 않았다. 클라우드·정션 등 재분석 지점 폴더의 재귀 색인은 현재 보수적으로 제외하며, 클라우드 공급자 연계·동기화 자체를 구현한 것은 아니다.

후속 증거는 `docs/task-id/pane-groups`의 `windows-build.log`, `linux-test.log`, `preferences-journey.json`, `preferences-light.png`, `preferences-dark.png`, `cloud-inventory.json`, `listing-probe.json`에 보관한다. 앞 절의 초기 실행 파일 해시·성능 수치는 해당 초기 빌드 기록이며, 현재 전달 파일 해시는 후속 `artifact.json`에 따로 기록한다. 메모리 경량화 목표와 교차 앱 수동 수락 검사 범위는 여전히 남아 있다.

현재 전달 실행 파일은 `dist/SDIR.exe`, 7,542,784 bytes, SHA-256 `ad3558e1d6625e36b1572a1f6d49c9aa3d2b8212ff892ae3599976f8b1d6a572`이다. `full-ui-journeys.log`에서 기존 탐색·파일 작업·검색, 정상 종료·복구, 새 그룹·설정 여정을 한 명령으로 순차 통과했다. `ui-smoke.json`·`ui-recovery.json`은 최신 회귀 검사로 갱신되며 앞 절의 초기 측정과 구별한다. 그룹·설정 검사 JSON은 실행한 파일 해시도 함께 기록한다.


## 복사·키보드·패널 검색 수정 검증

사용자의 실제 실패 보고 후 클립보드를 읽기 전용으로 확인했을 때 `Preferred DropEffect`만 있고 파일 목록 형식 `CF_HDROP`가 없었다. 사용 중인 clipboard-win 5.4.3의 `RawData` Setter는 쓰기마다 비우기를 수행한다. 파일 목록 다음 DropEffect를 같은 Setter로 쓰면서 파일 목록이 사라지는 코드 경로를 확인했다. 비우기는 한 번만 수행하고 두 형식을 추가하는 API로 수정했다. 기록 후 실제 파일 목록을 다시 읽어 일치하는지 확인하며, UI의 복사 완료도 작업 대기열 등록 시점에서 네이티브 완료 응답 시점으로 옮겼다.

키보드 파일 작업은 패널 탭·목록과 텍스트 입력창을 구분한다. 목록 클릭은 즉시 포커스를 잡고, 폴더 이동·검색 초기화로 목록 DOM을 교체하는 경우에만 현재 포커스를 확인한 뒤 복귀한다. 실제 키 여정에서 기존의 무조건 지연 포커스가 Ctrl+F 뒤 검색창 포커스를 빼앗아 Delete를 파일 삭제로 처리할 수 있음을 재현했고, 이를 제거한 뒤 검색창 편집이 파일 작업으로 넘어가지 않음을 검사했다. 테스트는 삭제 확인 창에서 중단돼 실제 삭제는 수행하지 않았다.

추가 모델 테스트는 접두어 연속 입력, 같은 문자 반복 순환, 시간 만료, 한글 문자열, 필터 범위 내 선택과 Shift 범위의 고정 anchor를 검증한다. Windows 코어·프로세스·네이티브 작업 테스트 18개와 Linux 테스트 17개가 통과했다.

실제 Windows 검증은 단순 핸들러 호출 대신 CDP의 마우스·키 입력을 사용한다. 별도 Windows Forms 프로세스가 앱이 내보낸 파일 목록과 DropEffect를 읽고, 반대로 Windows 클립보드 파일 목록을 생성해 앱으로 붙여넣는다. 이 방식은 실제 OS 클립보드의 교차 프로세스 호환을 확인하며, Windows 탐색기 UI를 직접 자동 조작한 검사와는 구별한다.

- 실제 클릭 → 문자 j 반복/ju 연속 → 가상 목록 바깥 항목의 선택과 스크롤, 방향키·Home·Shift 선택
- 실제 Ctrl+C → 두 파일의 CF_HDROP+복사 효과 확인 → 다른 패널 빈 영역 클릭 → Ctrl+V → 실제 내용 일치·원본 보존
- Ctrl+X → 이동 효과 확인 → 대상 탭에 포커스가 있는 상태에서 Ctrl+V → 대상 내용 일치·원본 제거
- 도구 모음 복사/붙여넣기와 한글 파일 이름·내용 확인
- 외부 Windows 클립보드 생산자의 복사·이동 형식을 받아 실제 파일 작업 확인
- 패널마다 다른 검색어 유지, Ctrl+F/F3, 검색창 Ctrl+A·Delete, Esc 초기화·목록 복귀, Ctrl+Shift+F 통합 검색

클립보드는 형식별 내용을 메모리에 백업하고, 테스트가 남긴 클립보드만 복원한다. 데이터 내용은 로그에 출력하지 않는다. 이번 입력 상태의 `Preferred DropEffect`를 보존·복원한 영수증은 `clipboard-restore.json`에 기록한다. 보존할 수 없는 형식이면 쓰기 전에 중단한다. Windows 충돌·권한·부분 완료 대화상자, 외부 OLE 드롭, 기본 앱 열기와 실제 탐색기 UI 여정의 기존 미확인 범위는 여전히 별도다.

패널 검색은 현재 폴더의 이름 일부 검색이다. 하위 폴더 검색이나 전체 드라이브 실시간 색인으로 확장했다고 주장하지 않는다. 하위 폴더 검색은 통합 검색의 명시적인 선택 폴더 색인을 사용한다. 증거는 `docs/task-id/clipboard-navigation`의 소스/실행 파일 해시, Windows·Linux 로그, `navigation-journey.json`, `clipboard-restore.json`, 최종 통합 여정 로그와 PNG에 보관한다.

같은 폴더 복사도 기존 공통 원본/대상 검사에서 거절되던 것을 수정했다. 동일 폴더 이동·재귀 대상 거절은 유지한다. 대상 안의 항목을 복사하는 경우 Windows Shell의 이름 충돌 회피 옵션을 적용해 별도 이름의 사본을 생성하며, 원본과 사본의 실제 내용을 네이티브 테스트와 UI 여정에서 확인한다. 같은 붙여넣기 요청에 대상 폴더 안의 항목이 포함되면 해당 요청의 이름 충돌은 자동 회피한다. 폴더 Enter 진입·Backspace 상위 이동 후 목록 포커스를 유지하는 실제 키 여정도 포함한다.

## 전체 기능 감사와 작업공간·탭 복원

이번 요청은 기존 노출 기능 감사 → 재현된 실패 수정·같은 여정 재검증 → 유용한 기능 추가 → 통합 회귀 순서로 진행했다. 추가 전 감사 결과는 `docs/task-id/journey-audit/audit-before-additions.json`, 추가 수락 기준은 `additions-spec.md`에 보관했다.

수정한 재현 실패는 다음과 같다.

- 목록이 F5 전파를 차단해 복원한 파일을 새로 읽지 못했다. 공통 단축키 경로에서 처리하고 휴지통 복원 후 실제 키 입력으로 확인했다.
- 설정의 800ms 지연 저장 전에 닫으면 마지막 배치를 잃었다. 단일 저장 작업자의 최종 스냅샷 저장 응답을 기다린 뒤 종료하도록 수정했다. 읽기 전용 설정 파일에서는 기존 파일을 보존하고 창 복귀·실패 안내·두 번째 닫기를 확인했다. 최종 정상 종료 측정은 약174ms였다.
- 네이티브 이름 충돌 창을 닫으면 `COPYENGINE_E_USER_CANCELLED`를 일반 오류로 표시했다. Windows 취소 HRESULT를 취소로 분류하고 두 파일의 내용 보존·취소 안내를 검증했다.
- 최소980×580 창 4분할에서 목록 높이가0px이었다. 작은 창의 도구 영역 높이·간격을 줄여 각 목록45~55px, 새 작업공간 여정에서는55px을 확보했다.
- 연속 탭 전환의 포커스 타이머가 실제 DOM 교체보다 먼저 실행돼 다음 키가 body로 유실됐다. 새 목록의 `onmounted`에서 명시된 요청만 처리하고 Ctrl+F/L로 요청을 취소하도록 수정했다. 마우스로 선택한 탭 헤더의 포커스는 보존하며 그 상태의 Ctrl+V를 다시 검증했다.

추가 기능은 이름 있는 작업공간 최대16개 저장·불러오기·같은 이름 갱신·기록 삭제, Ctrl+T/W/Shift+T 및 Ctrl+Tab/Shift+Tab, 패널별 닫은 탭 복원, 정상 재실행의 활성 탭·패널 복구다. 작업공간은 분할·그룹 이름·경로·활성 위치만 저장한다. 닫은 기록도 최대16개이고 파일 목록 버퍼를 보관하지 않으며 단위 테스트에서 Arc 해제를 확인했다. 테마와 즐겨찾기는 공유하고 닫은 탭 이력은 실행 중에만 유지한다. 새 의존성·서비스·자동 색인은 추가하지 않았다.

## 붙여넣기 후 작업 흐름과 참고 기능 적용

사용자의 복사/이동 후 대상 선택 누락을 기존 배포 파일에서 실제 키·OS 클립보드 여정으로 재현했다(`baseline-reproduction.log`). 데이터 복사 성공과 작업 후 사용 가능 상태를 구분해 검증 범위를 확장했다.

**변경한 흐름:** Windows가 완료한 최상위 항목의 실제 경로를 `IFileOperationProgressSink`로 받는다. 동일 폴더 사본의 바뀐 이름, 여러 파일, 폴더, 이름 변경·새 폴더 결과를 소스 이름 추측이나 디렉터리 차이 비교 없이 처리한다. 대상에서 결과를 선택하고 커서·앵커를 설정해 화면 안으로 스크롤하며 키보드 포커스를 넘긴다. 가리는 이름 필터는 해제한다. 정상화된 Shell 경로와 사용자가 입력한 경로의 대소문자가 다른 실패도 확인해 부모 폴더의 네이티브 정규 동일성과 실제 최종 이름으로 목록에 대응시켰다. 숨김 표시는 기존 설정을 존중하며 강제 숨김 파일 표시까지 구현한 것은 아니다.

파일 작업이 진행되는 동안 다른 위치나 검색창으로 이동했다면 새 작업을 방해하지 않는다. 제출 시점·목록 완료·새 DOM 표시 단계의 입력 세대를 확인한다. 작업 후 배경 목록 갱신으로 이전 선택을 복원할 때도 같은 검사를 적용해 새 검색어를 지우지 않도록 했다. 바뀐 폴더를 표시 중인 패널만 재조회하며, 취소/건너뛰기로 생성되지 않은 파일은 임의로 선택하지 않는다.

**참고 기능:** 기존에 검토한 MTT 고정 커밋의 문서·소스를 근거로 패널별 자세히·목록·큰 아이콘, 보기 상태의 작업공간/재시작 복원, 주소창의 상위 경로 메뉴, 복사/이동 배지와 잘라내기 흐림, 선택 반전(Ctrl+I)을 적용했다. [참고 기능 적용표](reference-features.md)에 각각의 근거와 여정을 연결했다. MTT 코드를 복사하지 않았으며 MTT 실행 성능을 측정한 결과도 아니다. goz-core 검색 통합은 유지했다.

아이콘 그리드는 폭에 따라 열 수를 바꾸고 열 수에 맞는 방향키·스크롤·가상 높이를 사용한다. 작은 4분할 창은54px 타일을 사용해 실제54.5px 목록에서도 한 항목 전체가 보임을 확인했다. 자세히·목록은 최대80행, 아이콘은 뷰포트와 열 수에 따른 범위(최대512개)만 그린다. 크기 관찰자는 패널당1개·최대4개이며 교체·제거 시 정리한다. 썸네일 파일 읽기, 추가 서비스, 새 자동 색인은 추가하지 않았다. 직접 의존성으로 추가한 windows-core0.62.2는 이미 사용 중인 Windows 바인딩의 전이 의존성이며 COM 인터페이스 구현 매크로 때문에 직접 명시했다.

**최종 검증:** Windows 단위21개+프로세스/네이티브4개(총25개), Linux 단위21개+프로세스3개(총24개)가 통과했다. Windows desktop check·release 빌드가 통과했고 최종 실행 파일로 기존13·복구3·개인화7·실제 키/클립보드8·Shell 감사8·작업공간6·새 보기/작업 흐름6·종료2, 전체 **53개 검사 묶음**을 한 회귀 실행에서 통과했다(`final-regression.log`). 같은 SHA-256 파일의 10만 파일 UI13개 묶음과 10만 파일 재조회 취소·복구·종료·재시작4개 묶음도 통과했다.

새 검사는 다중 복사·이동의 실제 내용과 선택/포커스, 같은 폴더 사본의 실제 이름 선택, F2 연속 작업, 숨기는 이름 필터 해제, 그리드 방향키/Shift 범위와 전체 필터 기준 반전, 보기 간 선택 유지·오프스크린 결과 표시, 최소 창 크기, 정확한 상위 폴더 이동, 3,000파일 폴더 복사 중 다른 패널로 이동해도 완료 뒤 포커스 유지, 보기 상태 복원, 소문자 대상 주소, 외부 클립보드 변경에 따른 표시 해제를 포함한다. 그리스 문자 경로의 대소문자와 중첩 폴더 복사의 최상위 결과 수는 네이티브 회귀 테스트로 확인했다. 테스트는 별도 프로필과 생성한 임시 파일만 사용했고 클립보드 복원 영수증도 성공했다.

산출물: **`dist/SDIR.exe`**, **7,919,616 bytes**, SHA-256 **`95518055cfdf65494dd248226d3ae85c5090ad91f05f5a7903fdc5805a2b874b`**. 모든 최종 UI 보고서의 해시는 이 파일과 일치하며 실행 중인 사용자 앱은 강제 종료하지 않았다. 소스 식별은 `docs/task-id/paste-reveal/artifact.json`, Windows 로그는 `canonical-results-build.log`와 `background-selection-build.log`, Linux 로그는 `linux-final-tests.log`, 전체 UI 증거는 `final-*.json`, `audit-journey.json`, `workspaces-journey.json`, `views-journey.json`, `fast-close.json`, `large-recovery.json`이다.

## Windows 기본 조작·전체 세션 복원·포터블 배포
